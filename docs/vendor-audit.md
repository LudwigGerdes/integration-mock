# Vendor spec audit

Generated by `integration-mock packs audit --out docs/vendor-audit.md` on 2026-08-30.
Every URL in `packages/packs/sources.yaml` was fetched and run through the
generator; the numbers below are what it actually produced, not estimates.

## Reading it

- **ok = NO — no spec url recorded yet** — nobody has researched that vendor. Not a
  dead vendor; an unfinished task.
- **ok = NO — <error>** — the URL is recorded but did not serve a spec.
- **skipped** — operations the generator declined: deprecated, no response
  defined, or an unresolvable path-level `$ref`.
- **warn** — routes served with a thin body because the spec had no example or
  schema for them.
- **gzip** — the size that would be cached. Anything over 2 MB gzipped is left
  `vendored: false` and fetched on demand.

## Caveats worth knowing

- **mailchimp** fetches fine but every one of its 181 path items is a `$ref` to a
  separate remote document. We do not follow those, so it generates 0 routes.
  The entry is kept for provenance rather than deleted.
- **clickup** and **snowflake** are genuine specs but cover a small slice of their
  vendor's surface (2 and 3 operations). Snowflake publishes only its SQL API.
- **github** is the largest at 11 MB, and its 201 warnings reflect a spec that
  leans on schemas rather than examples.
- **License columns are the catalogue's metadata**, not a redistribution grant
  from the vendor. Anything not clearly permissive is `vendored: false`, so its
  bytes are fetched rather than cached.

## Not researched (0)

All vendors in spec section 6.3 have been researched.

Google Sheets, Google Drive, Gmail and Microsoft Graph were **recovered**: they
are in the catalogue under provider keys (`googleapis.com:sheets`,
`microsoft.com:graph`) rather than under the vendor's common name, which a
name-based search missed. Their URLs are left empty
deliberately — a guessed URL is worse than a blank one, because it later looks
like a dead vendor rather than an unfinished lookup.

`generic-rest` ships no routes on purpose: it carries seed collections and lets
the generic resource store answer CRUD for a vendor we do not cover. Eject it
and set `domains` to point it at a real host.

The packs total ~18 MB, nearly all of it generated response bodies. Neither
capping nesting depth (2.06 → 1.71 MB) nor capping properties per object
(→ 1.24 MB, at the cost of mock fidelity) changes that materially — large
vendor schemas are simply wide. Recorded here so the trade-off is visible rather
than rediscovered.
